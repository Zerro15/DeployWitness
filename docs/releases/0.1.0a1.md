# DeployWitness 0.1.0a1 — draft release notes

> Draft for review. This release has not been published.

DeployWitness is an early local-first alpha for comparing Docker Compose configuration changes and explaining supported contract violations with deterministic static evidence.

## Included

- CLI commands for scanning one Compose file and comparing a base/head pair.
- Text, Markdown, and JSON reports with `PROVEN_CONFIG_BREAK`, `POTENTIAL_RISK`, `UNKNOWN`, and scoped `NO_FINDING` outcomes.
- Initial Compose models for services, dependencies, networks, mounts, and selected environment keys.
- A reusable GitHub Actions workflow that reads PR configuration as Git blobs, does not check out or execute PR code, and writes a Markdown job summary on the repository owner's runner.
- English and Russian setup, integration, and limitation documentation.

## Known limitations

- This is a pre-1.0 alpha; CLI and witness schema may change.
- It does not implement the full Compose specification, merge overrides, resolve `.env` or interpolation, or select profiles.
- A static witness proves only a supported configuration invariant; it does not prove a runtime outage or data loss.
- `NO_FINDING` covers implemented rules only.
- Fork-originated GitHub PR execution has not yet been verified end to end.
- There is no PyPI package or automatic PR comment in this draft.

See [supported Compose features](../SUPPORTED_COMPOSE_FEATURES.md), [installation](../GETTING_STARTED.md), and [upgrading](../UPGRADING.md).
