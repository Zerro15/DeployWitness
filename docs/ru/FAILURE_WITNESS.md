# Failure Witness

[English](../FAILURE_WITNESS.md) | [Русский](FAILURE_WITNESS.md) · [Индекс документации](README.md)

**Failure Witness** — структурированное и воспроизводимое объяснение изменения конфигурации. В текущей alpha это статические данные, вычисленные по двум проверенным Compose-файлам и явно заданным контрактам `x-deploywitness`. Инструмент не запускает приложение и не утверждает, что произошла runtime-авария.

## Уровни уверенности

| Статус | Значение |
| --- | --- |
| `PROVEN_CONFIG_BREAK` | Проверяемый конфигурационный инвариант выполнялся в базовой версии и нарушен в новой, либо в кандидате есть структурно недопустимая зависимость. Это доказывает нарушение конфигурации, но не runtime-сбой. |
| `POTENTIAL_RISK` | Обнаружено значимое изменение, однако явного контракта недостаточно, чтобы доказать нарушение ожидаемой конфигурации. |
| `UNKNOWN` | Ввод или значимая семантика Compose неполны либо не поддерживаются, поэтому надёжный вывод сделать нельзя. |
| `NO_FINDING` | Реализованные правила не обнаружили изменения, о котором нужно сообщить. Это не гарантия безопасности и не статус отдельного свидетельства. |
| `REPRODUCED_FAILURE` | Зарезервирован для будущего запуска воспроизводящего теста. Текущая alpha его не выдаёт. |

## Состав свидетельства

Схема версии `1` содержит идентификатор правила, статус, объект проверки, описание, факты базовой конфигурации, изменившиеся элементы, инвариант, ссылки на строки исходников, предложение по исправлению и декларативный статический тест. Значения переменных окружения и их хеши в отчёт не записываются. `verify_static` повторно разбирает входные файлы и независимо вычисляет ожидаемое свидетельство; принимается только полное совпадение существенных полей. Описание статического теста — это данные, оно не исполняется.

## Пример контракта

Объявите, что `api` и `db` должны иметь общую сеть:

```yaml
x-deploywitness:
  required_network_links:
    - from: api
      to: db
```

Если базовая версия удовлетворяет инварианту, а кандидат — нет, движок может выдать `PROVEN_CONFIG_BREAK`. Одного `depends_on` для такого сетевого контракта недостаточно. Без явного контракта удаление связи считается риском, а не доказанной аварией.

Контракт `required_mounts` требует сохранить подключение в заданной точке монтирования. Изменившийся источник может указывать на другое или пустое хранилище, но сам по себе не доказывает потерю данных. Остальные правила описаны в разделе [поддерживаемые возможности Compose](SUPPORTED_COMPOSE_FEATURES.md).
