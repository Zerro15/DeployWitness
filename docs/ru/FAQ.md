# Частые вопросы

[English](../FAQ.md) | [Русский](FAQ.md) · [Индекс документации](README.md)

### DeployWitness — это линтер?

Он сравнивает две конфигурации Compose и проверяет изменения по моделируемым контрактам. Если изменение выглядит важным, но доказательств недостаточно, инструмент сообщает о риске.

### Он предсказывает аварии или доказывает runtime-сбой?

Нет. `PROVEN_CONFIG_BREAK` означает, что нарушен проверяемый конфигурационный инвариант. Это не значит, что во время работы наблюдалась ошибка запроса или процесса. Статус `REPRODUCED_FAILURE` зарезервирован и пока не выдаётся.

### Нужно ли заранее писать контракты?

Нет, чтобы разобрать или сравнить файлы, контракты не обязательны. Без контракта значимое удаление может получить `POTENTIAL_RISK`. Явные декларации `x-deploywitness` позволяют доказать нарушение поддерживаемых инвариантов.

### Что делает `scan`?

Находит один Compose-файл со стандартным именем и показывает число сервисов. Изменения эта команда не сравнивает. Для этого используйте `check --base ... --head ...`.

### Запускает ли инструмент Docker Compose, контейнеры или код проекта?

Нет. Статический анализатор разбирает ограниченное подмножество YAML и не запускает команды из анализируемого репозитория. Docker не нужен.

### Поддерживаются ли overrides, profiles и `.env`?

В этой alpha — нет. Текущий парсер не может надёжно разрешить эти случаи; результат будет `UNKNOWN` или неполным. См. [поддерживаемые возможности](SUPPORTED_COMPOSE_FEATURES.md).

### Конфигурация отправляется на сервер?

Нет. Анализ локальный и не выполняет сетевых запросов. Доступ к сети может понадобиться при установке Python-зависимостей.

### Есть ли готовая проверка PR или опубликованный пакет?

Пока нет. Пакет не опубликован в PyPI. GitHub workflow запускается вручную на фиксированных файлах репозитория и не получает base/head PR автоматически.

### Что означает `NO_FINDING`?

Только то, что реализованные правила не нашли проблему во входных данных. Это не гарантия корректности или безопасности конфигурации.
