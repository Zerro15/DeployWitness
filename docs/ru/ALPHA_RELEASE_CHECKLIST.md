# Checklist alpha-релиза

[English](../ALPHA_RELEASE_CHECKLIST.md) | [Русский](ALPHA_RELEASE_CHECKLIST.md) · [Индекс документации](README.md)

Этот checklist готовит `0.1.0a1`, но не публикует релиз или пакет.

## Перед тегированием

- [ ] Объединить только проверенные PR; убедиться, что в `main` попали нужные код и документация.
- [ ] Зафиксировать версию и commit. Сверить `pyproject.toml`, `CHANGELOG.md` и release notes.
- [ ] Запустить `python -m pytest`, `python -m ruff check .`, `python -m mypy src`, `python scripts/check_i18n.py` и `git diff --check`.
- [ ] Собрать `python -m build` и проверить состав wheel и sdist.
- [ ] Создать `SHA256SUMS.txt` для точных wheel и sdist, проверить обе записи и приложить файл к релизу.
- [ ] Создать чистое виртуальное окружение Python 3.12, установить wheel, выполнить `deploywitness --help`, `deploywitness version` и пример из репозитория.
- [ ] Убедиться, что зависимости Actions и reusable workflow закреплены за проверенными commit; проверить CI для точного commit.
- [ ] Проверить [таблицу поддерживаемых функций](../SUPPORTED_COMPOSE_FEATURES.md), ограничения, инструкции на двух языках и руководство по обновлению.
- [ ] Если настоящий запуск PR из fork всё ещё не проверен — явно указать это.

## План GitHub Release

1. После отдельного одобрения сопровождающего создать annotated tag `v0.1.0a1` на проверенном commit.
2. Создать GitHub pre-release с текстом из [`releases/0.1.0a1.md`](../releases/0.1.0a1.md); приложить wheel, sdist и `SHA256SUMS.txt` только после проверки содержимого и контрольных сумм.
3. Добавить ссылки на [установку](GETTING_STARTED.md), ограничения и обновление. Не называть alpha готовой к production.

## Первое публичное объявление

1. Публиковать GitHub pre-release только после выполнения checklist выше и с явным указанием, что fork-тест ещё не выполнен.
2. Сначала разместить объявление в GitHub Discussions проекта или в разделе релиза README; дать прямые ссылки на релиз, установку, таблицу возможностей и политику безопасности.
3. Ограничить обещания: ранняя Compose alpha, поддерживаемые статические проверки, runner пользователя, отсутствие backend и телеметрии, известные ограничения. Не заявлять о полной совместимости с Compose, предсказании runtime-аварий или готовности к production.

## План PyPI (требует отдельного одобрения)

Публикация в PyPI — отдельное действие, не часть создания GitHub Release. Если она отдельно одобрена, используйте trusted publishing из GitHub environment проекта либо другой контролируемый сопровождающим способ. Публикуйте только проверенные артефакты tagged commit, затем проверьте установку в чистом окружении. Не добавляйте долгоживущие PyPI credentials в секреты репозитория для этой alpha.

## Возможности alpha

| Область | Поддерживается | Если данных недостаточно |
| --- | --- | --- |
| CLI | `scan`, сравнение файлов через `check`, отчёты text/Markdown/JSON | Ошибка для некорректного входа |
| Compose | Один эффективный YAML-файл на сторону; сервисы, `depends_on`, сети, mounts, выбранные env keys | `UNKNOWN` для неразрешённых возможностей |
| Witness | Статическое доказательство поддерживаемых явных контрактов; риски без контракта | Runtime-воспроизведение не заявляется |
| GitHub PR | Reusable workflow, сравнение base/head blob, Markdown job summary | `UNKNOWN` для добавленных/удалённых файлов и неоднозначных структур |
| Исполнение | Локальный процесс или CI runner пользователя; backend анализа отсутствует | Для установки зависимостей нужен доступ к пакетам; затем анализ офлайн |

См. [черновик release notes](../releases/0.1.0a1.md) и [ограничения Compose](../SUPPORTED_COMPOSE_FEATURES.md).
